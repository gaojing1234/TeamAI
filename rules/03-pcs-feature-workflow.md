# 走总控流程实现一个研发需求

对下面这个需求，按「总控 Agent 编排」流程推进，**不要自己写需求契约或 C 代码**。

需求：`{{args}}`

---

## 执行步骤（逐条推进，每步都要向用户汇报）

1. **建运行** — 调用 `plan_feature`，把用户需求原文传给 `requirement`。
   若需求里能看出目标平台/型号就填 `platform`，看不出就留空（不要猜）。
   拿到 `run_id` 后，把任务 DAG 表格 + 「待接入节点」清单展示给用户。

2. **需求分析** — 调用 `run_step`（不传 node，自动取就绪节点）。
   完成后汇报：需求条数、验收标准条数、**警告原样转述**。

3. **卡点：需求契约签发** — 状态里出现 `pending_gates: requirement` 时**停下来**。
   用 `get_artifact` 读需求契约，向用户摘要展示：功能条目表、待确认项（第 7 节必须展示全）。
   然后**问用户是否签发**，不要自己决定。

4. **签发后继续** — 用户确认后调用 `approve_gate`（decision=approve，comment 填用户意见）。

5. **代码生成** — 再调一次 `run_step`（此时 code 节点才变成 ready）。

6. **卡点：代码合并** — 出现 `pending_gates: code_merge` 时再次停下来。
   用 `list_artifacts` + `get_artifact` 展示：生成了哪些文件、各多少行、需求覆盖率、
   设计说明里的自检结果与待确认项处理。**问用户是否合并**。

7. **收尾** — 汇报终态：每个节点状态、产物编号与磁盘路径。
   提醒用户：待接入节点（单元测试 / 仿真模型 / 系统测试）接上智能体后会自动解锁，无需改总控。

---

## 纪律提醒

- 一次只推进一步，不要连打 `run_step`
- 卡点必须由用户决定，**绝不代签**
- 失败时先 `get_run_status` 看原因并原样转述，让用户选 `resolve_failure` 的 action
- 不要把 `get_artifact full=true` 的长正文整段贴回对话；展示时只摘关键片段
