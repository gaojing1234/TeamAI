# 公司嵌入式 C/C++ 编码规范映射

> 来源：用户提供的《嵌入式C_C++编码规范.docx》。本文件只摘录对编码决策有影响的规则，并用嵌入式实现视角改写；原文中的“规则”为强制项，“建议”为必须考虑项。

## 优先级

1. 目标平台安全约束、项目明确构建配置和既有公共接口契约。
2. 公司规范中的“规则”。
3. 项目已有风格与公司规范中的“建议”。
4. `coding-rules.md` 中的通用默认规则。

为不扩大修改面：

- 新增代码按公司规范执行。
- 修改风格不一致的存量代码时，优先沿用该函数/模块的既有风格；不要做无关批量格式化。
- 如果公司规范与现代安全规则冲突，选择能保持正确性、实时性和可验证性的方案，并在交付说明中指出冲突与理由。

## 排版与格式

- 缩进为 4 个空格；编辑器可将 TAB 配置为 4 空格，禁止混用不同宽度的缩进。
- 相对独立程序块之间、变量声明之后加一个空行；不使用连续多行空行。
- 一行小于 80 个字符；长表达式在低优先级操作符处换行，操作符放在新行开头，并保持缩进整齐。
- 一行只写一条语句；除变量定义外不使用逗号表达式。
- `if`、`for`、`do`、`while`、`case`、`switch`、`default` 独占一行；控制语句执行体无论多少行都使用 `{}`。
- `{` 和 `}` 各独占一行并对齐；函数、结构、枚举、类及其控制块统一采用该风格。
- 对等操作符前后保持一致空格；`[]`、`.`、`->` 等紧密操作符前后不加空格。
- 混合不同优先级操作符时，用括号显式表达求值顺序；不要依赖优先级阅读代码。
- 预编译宏定义前一行为说明；连续多行宏要有明确缩进；夹在代码中的编译开关从第一列开始。
- 标准库头文件用 `#include <filename.h>`；项目/非标准头文件用 `#include "filename.h"`。

## 注释与文档

- 有效注释量必须达到源代码行数的 50% 以上；注释应解释功能、意图、约束和依据，而不是重复语法。
- 说明性文件与源文件头部列出：版权、版本、日期、作者、模块目的、主要内容/功能、与其他文件关系、主要函数说明和修改日志。
- 函数头列出：目的/功能、输入参数、输出参数、返回值、调用关系；可记录单元测试中曾暴露的问题。
- 数组、结构体、类、枚举、联合体必须注释；结构体每个成员说明用途、取值范围和约束。
- 全局变量和静态变量必须说明功能、取值范围、读写函数/任务、访问时序和注意事项。
- 物理寄存器的位/字段含义和初始化值必须逐项注释，并注明手册、版本和章节来源。
- 注释放在被描述代码的上一行或行末右侧，缩进与代码一致；禁止插在一行代码或表达式中间。
- 因特殊情况需要 fall-through 的 `case`，必须在进入下一分支前显式注释。
- 大段废弃代码用 `#if 0` 或版本控制处理，不用块注释保留。

## 命名与基础类型

### 标识符

- 变量名 = 类型前缀 + 有意义的名称；类型前缀之后每个单词首字母大写。`i`、`j`、`k` 仅可用于局部循环变量。
- 宏和常量全大写，用下划线分隔；函数式宏参数和结果必须完整加括号。
- 公司规范的全局函数名使用大写字母开头的单词组合，如 `ReadAdcValue`；若项目既有代码使用其他风格，修改该模块时保持一致。
- 类名用大写字母开头的单词组合；类数据成员使用 `m_` 前缀。
- 单词使用完整拼写；采用特殊约定或不常见缩写时必须注释。
- 不使用仅大小写不同的相似标识符；局部变量不得与公共变量同名。
- 变量名使用名词或“形容词 + 名词”；函数名使用动宾短语。

### 类型前缀

| 类别 | 标准类型/对象 | 前缀 |
|---|---|---|
| 有符号 8 位 | `int8` | `i8_` |
| 无符号 8 位 | `uint8` | `u8_` |
| 有符号 16 位 | `int16` | `i16_` |
| 无符号 16 位 | `uint16` | `u16_` |
| 有符号 32 位 | `int32` | `i32_` |
| 无符号 32 位 | `uint32` | `u32_` |
| 32 位浮点 | `float32` | `f32_` |
| 64 位浮点 | `float64` | `f64_` |
| 结构体变量 | `struct` | `st_` |
| 结构体成员 | member | `m_` |
| 位域/位变量 | bit | `b_` |
| 联合体变量 | `union` | `un_` |
| 指针 | pointer | `p_` |

### 层级前缀

| 层级/函数类别 | 前缀 |
|---|---|
| 驱动层/驱动函数/驱动文件 | `Drv_` |
| 数据处理层/数据处理函数/数据处理文件 | `Dat_` |
| 算法层/算法函数/算法文件 | `Alg_` |
| 应用层/应用函数/应用文件 | `App_` |

常用缩写须全项目统一并可被团队识别，例如 `addr`、`arr`、`avg`、`buf`/`buff`、`chk`、`calc`、`cnt`、`cmd`、`ctrl`、`curr`、`dst`/`dest`、`err`、`freq`、`func`、`idx`、`init`、`len`、`msg`、`ptr`、`recv`、`ref`、`res`、`src`、`stat`、`str`。其他缩写在命名处或模块命名约定中说明。

### 类型使用

- 禁止在接口中直接依赖 `char`、`int`、`long` 等默认宽度；使用公司统一基础类型或项目平台别名。
- 不做隐式类型转换；必要转换必须显式、局部化并有宽度/范围依据。
- 不把宽度大于目标类型的值或超出目标范围的常量赋给目标变量。
- 运算前检查截断、溢出、下溢、有符号/无符号提升和浮点精度。
- 尽量少用无符号类型、浮点类型和 `union`；使用时必须在接口和测试中覆盖混合运算、精度和重解释风险。

## 变量、结构与初始化

- 删除不再使用的变量和全局变量；局部变量不得超出最小有效作用域。
- 严禁把未初始化变量作为右值；所有局部变量在首次使用前有明确值。
- 指针有确定目标时初始化为目标地址，否则初始化为 `NULL`。
- 系统初始化阶段对必要 RAM 区清零或显式赋初值；不能依赖随机上电内容。
- 公共变量定义功能、取值范围、访问者和相互关系；尽量设计为单一写者、多读者。
- 不要用单个 bit 表示复杂状态；优先使用多位字段或枚举，并明确非法值/默认值。
- 结构体只抽象一种事务；成员布局考虑可读性、对齐、空间和向前兼容。
- 不同编译单元的全局对象初始化顺序不可依赖；需要顺序时用显式初始化函数建立。

## 函数与可重入性

- 函数规模控制在 200 行以内；一个函数只完成一件事，避免多用途和控制参数过多。
- 函数返回值与函数类型一致；`non-void` 函数所有退出路径都有显式带表达式 `return`。
- 调用方必须处理有意义的返回值；显式忽略时写明理由，不用无意义的 `(void)` 吞错。
- 检查所有参数输入和其他输入（全局变量、文件、外设缓存、队列等）的有效性。
- 仅输入用的指针参数加 `const`；基本类型按值传递，复合类型按指针/引用传递以减少拷贝。
- 参数名完整表达方向；使用公司风格拷贝类接口时，目的参数在前、源参数在后；若项目或标准库习惯相反，以项目习惯为准。
- 不把参数当工作变量反复修改；必要时先拷贝到局部语义变量。
- 可重入函数使用全局变量时，必须用关中断、信号量或其他等价同步机制保护。
- 中断可重入路径使用普通局部变量，避免共享静态工作区；ISR 调用的函数必须可重入，避免非 ISR-safe API。
- 表达式中的 `++`/`--` 单独成行，不与其他表达式混合。
- 函数扇出小于 7；高扇入、低扇出的公共小函数是好的，复杂调度函数需拆分。
- 关键算法画出数据流/控制流，必要时用第二种算法或参考结果交叉验证。

## 控制流与质量保证

- `if` 尽量有 `else`；无论是否执行动作，`switch` 必须有 `default:`，空处理用 `default: break;`。
- 禁止 `goto`。
- 禁止在 `if`、`while`、`for` 条件中写赋值表达式。
- 循环体内不修改循环控制变量；优先使用 `0 <= x < N` 半开半闭区间。
- 减少循环嵌套；把不随循环变化的判断移出循环；最忙循环放在最内层。
- 避免调用频繁路径的除法，特别是浮点除法；不用移位/技巧性代码替代可读乘除，除非有测试证明收益。
- 删除永远不执行的垃圾代码和无效计算。
- 只访问属于自己的存储空间；释放后的内存、句柄、队列和对象不得再引用。
- 函数内申请的内存、文件句柄、锁、缓冲等资源必须在所有退出路径释放或归还。
- 启动时初始化变量和运行环境，并对加载配置、持久化数据和通信帧做一致性校验。
- 防止差一错误、边界值错误、数组越界、上溢/下溢、精度损失和易混淆操作符。
- 不随意修改其他模块设置；公共接口变化需要评审所有调用方和兼容性。
- 尽量使用标准 C/C++ 和抽象层，避免依赖硬件/操作系统细节；仅在有明确需求和测试时使用内联汇编。
- 危险操作（写 Flash、擦除数据、控制执行器、修改系统配置）必须有权限、校验、确认和失败安全策略。

## 宏与硬件初始化

- 宏表达式对每个参数和整个结果完整加括号。
- 语句式多条表达式宏使用 `do { ... } while (0)` 包裹；确保调用处需要分号且分支展开安全。
- 宏参数在展开中只能出现一次，不得导致参数多次求值或被修改。
- C++ 中用 `const`、`constexpr` 和内联函数取代宏常量/宏代码。
- 兼容多种硬件版本的软件启动时先读取硬件版本，再选择寄存器配置和初始化路径。
- 初始化片内外设和外围芯片时保持顺序正确，并记录时钟、复位、引脚复用和中断使能依赖。
- 必要时启动阶段检测片内/片外 RAM，确认后再初始化，检测结果纳入诊断。
- 看门狗必须明确超时预算、喂狗任务、窗口和复位后的安全状态；不得用盲目喂狗掩盖死循环。
- ISR 只保留必须在中断上下文完成的工作，其余通过标志、队列或回调交给任务处理。

## C++ 专项

### 类布局

类声明顺序：`public:`、`protected:`、`private:`；每一块内依次为：

1. `typedef`/`using` 和 `enum`
2. 常量
3. 构造函数
4. 析构函数
5. 成员函数（含静态成员函数）
6. 数据成员（含静态数据成员）

- 类名和继承父类同一行；类作用域花括号独占一行；访问控制关键字不缩进，成员缩进 4 空格。
- `.cpp` 中函数定义顺序尽量与声明顺序一致。

### 常量、构造和继承

- 不在类声明中初始化 `const` 数据成员；按构造函数初始化列表初始化。
- 不强制转换 `const`；这会破坏 ROM/只读 RAM 中的对象并导致未定义行为。
- 构造之后不变的成员定义为 `const`；能用 `const` 常量取代宏常量时优先使用。
- 成员定义顺序与初始化列表顺序必须一致。
- 构造/析构函数不调用虚函数；构造函数不做过多业务逻辑。
- 派生类初始化列表显式调用基类构造函数；继承体系基类析构函数使用 `virtual`。
- 单参数构造函数使用 `explicit`，除非确实需要隐式转换。
- is-a 关系使用 `public` 继承；has-a 使用组合；仅按实现复用时可使用 `private` 继承。
- 不遮掩继承名称，不重定义继承的 non-virtual 函数和缺省参数值。

### 内存与返回值

- 使用 `malloc/new` 后立即检查空指针；`free/delete` 后立刻置空指针。
- `malloc/free` 与 `new/delete` 不混用；释放对象数组必须使用 `delete[]`。
- `new[]` 对象只能使用无参构造函数；硬实时和长期运行路径仍优先静态/池化分配。
- 不返回指向栈内存的指针或引用；明确返回值是拷贝、指针还是引用。
- 按值传入大型对象时改为 `const &`，避免不必要的构造和析构。
