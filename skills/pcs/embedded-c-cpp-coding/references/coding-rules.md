# 嵌入式 C/C++ 编码规则

## 通用规则

### 项目适配

- 先读取项目内已有代码、格式化配置、编码规范和警告配置；已有规则优先于本默认规则。
- 不做与本任务无关的格式化、头文件重排、命名改造或框架迁移。
- 修改公共接口前检查所有调用点；无法确认时显式列出待确认影响面。
- 平台相关代码通过明确的适配层隔离，不把寄存器地址、厂商 HAL 细节和业务逻辑混在同一层。

### 命名

- 类型、函数、变量和宏的命名必须能表达用途；不使用单字母变量，循环索引等局部例外可用 `i`、`j`。
- 函数名使用动词或动词短语，例如 `motor_enable`、`ReadAdcValue`；同一项目内语言风格保持一致。
- 模块公开 API 带模块前缀，例如 `flash_storage_read`，避免与 HAL、标准库或其他模块冲突。
- 宏、常量和配置项使用全大写，带模块前缀；函数式宏必须完整加括号，禁止同名宏产生隐藏控制流。
- 布尔函数或变量使用 `is_`、`has_`、`can_`、`_enabled` 等含义明确的前后缀。

### 文件与模块

- `.c/.cpp` 包含对应 `.h` 作为第一处项目头，能尽早发现接口与实现不一致。
- 头文件使用 `#pragma once` 或项目规定的 include guard；公开头只暴露必要类型、常量和函数。
- 头文件必须自包含，不依赖包含者预先包含其他头；可前置声明的类型不要强制包含定义。
- 内部函数和全局变量使用 `static`；跨模块数据通过函数接口或明确的 owner 模块访问。
- 裸机/RTOS 模块尽量提供 `init`、`start/stop`、业务操作和状态查询等清晰生命周期函数。

### 函数

- 一个函数只做一件事，控制流和嵌套保持可读；超过约 80 行或混合多个抽象层次时考虑拆分。
- 避免深层嵌套，可通过提前返回处理无效输入；项目要求单出口时遵循项目要求，并让每个出口状态明确。
- 不使用递归，除非目标栈、深度和平台均已证明有界，并写入设计说明。
- 每个函数明确失败行为：返回状态码、布尔成功标志、输出参数或异常策略，不在模块间混用。
- 指针参数必须定义所有权、可空性、生命周期和写入范围；输出参数通常放在输入参数之后。
- 初始化函数失败时清理已申请资源，并返回可区分的错误码。

## 类型和数据

- 跨接口、存储器和通信协议的数据使用 `stdint.h` 定长类型；内部计数、索引和尺寸类型根据平台明确选择。
- 不依赖 `char`、`short`、`int`、`long` 的具体宽度；序列化按字节显式转换，不直接以结构体布局传输。
- 涉及有符号/无符号转换、位字段、浮点比较、指针转换和 `sizeof` 时必须显式、可解释。
- 位操作使用无符号类型；移位计数必须检查小于位宽，不依赖带符号左移的隐式行为。
- `struct` 涉及外设、总线、Flash、网络协议或对齐敏感内存时，明确 `#pragma pack`、`alignas` 与字节序策略。
- `union` 只用于明确的重解释场景，例如寄存器映射或协议字段视图，不能用于绕过类型系统。
- 常量使用 `static const`、`constexpr` 或宏定义；魔法数字必须命名，或在局部语义中显而易见。

## 内存与资源

- 硬实时、长期运行和中断路径使用静态分配、对象池、预分配缓冲或栈对象；禁止 `malloc/new/free/delete`，除非项目明确允许并有失败策略。
- 堆若不可避免，必须检查分配失败、限制生命周期、防碎片，并禁止在中断或持锁路径分配。
- 所有缓冲区访问必须带容量和长度；`memcpy`、`strcpy`、`sprintf` 等无界操作不得用于外部输入。
- 读取硬件 FIFO、DMA 描述符、通信帧和文件内容时检查长度、边界、溢出、截断和回卷。
- DMA 访问需要明确缓存一致性、对齐、所有权和完成通知；不要在同一区域混用 CPU 修改和 DMA 修改。
- 动态 C++ 资源优先 RAII，关闭中断或持锁期间不触发可能阻塞的分配或析构。

## 中断、并发与硬件

### 中断服务程序

- ISR 保持短小、可预测，只完成采样、标志置位、队列/环形缓冲、限值比较和必要保护动作。
- ISR 中不调用 `printf`、`malloc`、文件 I/O 或非 ISR-safe 的 RTOS API。
- ISR 与主循环共享数据必须使用原子访问、临界区、禁中断窗口、无锁单生产者单消费者队列或双缓冲，并注明读写双方。
- ISR 返回前必须处理中断标志，并考虑外设溢出、总线错误、噪声和异常恢复。

### 临界区与同步

- 临界区覆盖共享数据的最小必要区，不在其中做复杂计算、长循环、阻塞等待或调用外部回调。
- 保存/恢复中断状态，支持嵌套临界区；不得用简单布尔开关破坏已有临界区。
- RTOS 任务优先级、互斥锁优先级继承、队列长度、超时和阻塞关系必须明确。
- 优先使用不可变数据、快照、原子计数和单写多读结构，减少共享范围。
- 跨核、跨 FPGA、跨 DMA 的访问需要内存屏障、缓存维护和顺序要求说明。

### 寄存器与外设

- 寄存器映射使用厂商头文件、明确的 `volatile` 结构体或 `readl/writel` 风格 API，不复制无来源的寄存器定义。
- 读写有副作用的寄存器前确认清除标志、状态位和 FIFO 顺序；避免重复读状态导致数据丢失。
- 外设时钟、引脚复用、中断向量、DMA 通道和低功耗状态必须在初始化路径中一致配置。
- 延时使用定时器或系统滴答；避免依赖编译器优化的忙等循环。

## 错误处理与可观测性

- 错误码使用模块或项目统一定义，避免用 `0/-1` 混合多种失败原因。
- 日志必须分级、可裁剪、长度有界；生产或 hard-real-time 路径可用错误位图、计数器和诊断缓冲替代阻塞日志。
- 不吞掉错误；暂时忽略的错误必须有明确理由、限流或诊断。
- 断言只用于不可达的程序员错误，不用于运行时输入校验；生产构建策略由项目配置决定。
- 故障处理定义安全态，例如停机、封锁 PWM、释放继电器、复位外设或记录诊断数据，不得盲目继续。

## C++ 子集

嵌入式 C++ 必须先确认项目是否禁用异常、RTTI 和动态内存；不确定时按禁用处理，除非现有构建明确启用。

- 推荐使用 `constexpr`、`enum class`、`using`、RAII、命名空间、简单模板和 `<cstdint>`。
- 禁用异常时，不写会抛异常的标准库/语言路径；构造失败改为 `init()` 返回错误码。
- 禁用 RTTI 时，不使用 `dynamic_cast` 和 `typeid`；多态用于初始化完成的静态对象图，不在硬实时关键路径引入不可预期分配。
- 不在硬实时或长生命周期路径使用需动态增长的标准容器，例如 `std::vector`、`std::string`，除非项目明确批准并有失败策略。
- 构造和析构不得访问未初始化硬件；外设对象提供显式初始化和反初始化。
- 模板限制在类型安全、编译期配置和零成本抽象，避免大型递归实例化和复杂诊断。

## 注释与文档

- 公共接口注释说明用途、参数、返回值、错误、并发要求、ISR 安全性、阻塞行为和资源所有权，不解释显而易见的语法。
- 复杂算法、定点缩放、滤波器系数、寄存器顺序、内存屏障和单位换算必须写依据。
- 时序、内存、栈、优先级和总线带宽预算写入模块设计或接口说明。
- 注释语言遵循项目主语言；修订硬件相关常量时同步更新来源、手册版本和章节。
