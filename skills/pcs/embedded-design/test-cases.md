# embedded-design 技能测试用例

## 测试目标

验证 `embedded-design` 技能在不同场景下能否正确加载、路由并生成符合预期的设计产物。

---

## 测试用例 1：单方向 - MCU 架构设计

### 输入

```
请帮我设计 100kW 光伏并网逆变器的 MCU 侧软件架构，包括 RTOS 选型、任务划分、故障隔离和 Bootloader 设计。
```

### 预期行为

| 检查项 | 预期结果 |
|--------|----------|
| 技能加载 | 自动加载 `embedded-design` 技能 |
| 参考文档 | 读取 `references/mcu-design.md` |
| RTOS 选型 | 输出 FreeRTOS/RT-Thread/Zephyr 对比表，给出推荐及理由 |
| 任务划分 | 输出至少 6 个任务的优先级、周期、WCET 表 |
| 故障隔离 | 输出 4 层保护架构（FPGA → MCU → DSP → HMI） |
| Bootloader | 输出状态机及 Flash 分区布局 |
| 输出格式 | 包含架构图（ASCII）、状态机、流程图 |

### 验证标准

- [ ] 架构图包含硬件层、驱动层、OS 层、中间件层、应用层
- [ ] 任务表包含优先级、周期、最坏执行时间
- [ ] 状态机包含 INIT、STANDBY、RUNNING、FAULT、RECOVERY 状态
- [ ] 流程图覆盖启动流程和故障处理流程
- [ ] Flash 分区包含 Bootloader、主固件、备份固件、OTA 临时区

## 测试用例 2：单方向 - DSP 控制方案

### 输入

```
帮我设计储能逆变器的 DSP 控制方案，需要支持 PQ 并网和 VSG 离网双模式，包含 PLL、电流环和 MPPT 算法选型。
```

### 预期行为

| 检查项 | 预期结果 |
|--------|----------|
| 技能加载 | 自动加载 `embedded-design` 技能 |
| 参考文档 | 读取 `references/dsp-design.md` |
| 双模式 | 输出 PQ/VSG 控制架构图及模式切换逻辑 |
| PLL | 输出 PLL 类型对比表（SRF-PLL/DSRF-PLL/DSOGI-PLL 等） |
| 电流环 | 输出 dq 坐标系下级联 PI 控制框图 |
| MPPT | 输出 MPPT 算法对比表及 P&O 流程图 |
| 开关频率 | 输出死区补偿方案 |

### 验证标准

- [ ] 包含 PQ 模式和 VSG 模式的控制框图
- [ ] PLL 对比表包含锁定时间、THD 抑制能力、复杂度
- [ ] 电流环框图包含解耦和前馈
- [ ] MPPT 流程图包含 ΔP/ΔV 判断逻辑
- [ ] 包含控制环路时序预算（电流环 < 10µs）

## 测试用例 3：单方向 - FPGA 数据通路

### 输入

```
为逆变器设计 FPGA 侧数据通路和硬件保护方案，需要 ADC 采样、抽取滤波、RMS 计算和故障锁存功能。
```

### 预期行为

| 检查项 | 预期结果 |
|--------|----------|
| 技能加载 | 自动加载 `embedded-design` 技能 |
| 参考文档 | 读取 `references/fpga-design.md` |
| 顶层架构 | 输出 Verilog 模块层次结构 |
| 时钟规划 | 输出时钟域划分及 CDC 策略 |
| 数据通路 | 输出 CIC+FIR 抽取滤波链 |
| RMS 计算 | 输出 RMS 计算流水线 |
| 保护逻辑 | 输出故障检测与锁存逻辑，响应时间 < 500ns |
| IP 选型 | 输出 SPI/CAN 通信 IP 对比表 |

### 验证标准

- [ ] 顶层模块包含 adc_interface、data_path、protection、comm_interface
- [ ] 时钟域至少 3 个（ADC、系统、通信）
- [ ] 抽取滤波包含 CIC + FIR 两级
- [ ] 保护逻辑包含阈值比较、故障锁存、去抖
- [ ] 资源估算表包含 LUT、FF、BRAM、DSP 列

## 测试用例 4：单方向 - Linux 应用架构

### 输入

```
设计逆变器 Linux 侧应用架构，包括进程划分、Modbus/MQTT 通信栈、数据存储和 OTA 升级方案。
```

### 预期行为

| 检查项 | 预期结果 |
|--------|----------|
| 技能加载 | 自动加载 `embedded-design` 技能 |
| 参考文档 | 读取 `references/linux-design.md` |
| 进程划分 | 输出进程优先级表（SCHED_FIFO/SCHED_RR/SCHED_OTHER） |
| 驱动框架 | 输出 SPI/CAN 驱动结构 |
| 通信栈 | 输出 Modbus TCP/RTU、MQTT、IEC 104 协议栈 |
| 存储 | 输出 SQLite 数据库 Schema |
| OTA | 输出 SWUpdate 配置及 OTA 状态机 |
| HMI | 输出 Web HMI 架构图 |

### 验证标准

- [ ] 进程表包含至少 6 个进程及优先级
- [ ] 通信栈覆盖 Modbus 和 MQTT
- [ ] SQLite 表包含 measurements、events、waveforms
- [ ] OTA 状态机包含 DOWNLOADING、VERIFYING、INSTALLING、ROLLING_BACK
- [ ] 文件系统布局包含 boot、rootfs、overlay、data、recovery

## 测试用例 5：多方向集成 - 全系统架构

### 输入

```
为 100kW 光伏并网逆变器设计完整嵌入式系统架构，需要 MCU、DSP、FPGA 和 Linux 四个方向的方案设计，以及它们之间的接口定义。
```

### 预期行为

| 检查项 | 预期结果 |
|--------|----------|
| 技能加载 | 自动加载 `embedded-design` 技能 |
| 参考文档 | 读取全部 4 个参考文档 |
| MCU 方向 | 输出软件架构、任务划分、状态机 |
| DSP 方向 | 输出控制架构、PLL、电流环 |
| FPGA 方向 | 输出数据通路、保护逻辑 |
| Linux 方向 | 输出进程架构、通信栈 |
| 跨方向集成 | 输出接口控制文档（ICD） |
| 故障传播 | 输出 FPGA → MCU → DSP → Linux 故障传播图 |
| 时序预算 | 输出端到端延迟分析 |

### 验证标准

- [ ] 四个方向均有独立的架构图和状态机
- [ ] ICD 包含 CAN 帧定义（ID、数据域、周期）
- [ ] ICD 包含 SPI 寄存器映射
- [ ] 故障传播图覆盖 4 层保护
- [ ] 时序预算满足：FPGA < 1µs，MCU < 1ms，DSP < 10ms，Linux < 100ms
- [ ] 输出物总数 ≥ 5（架构图 ×4 + ICD + 故障图 + 时序表）

## 测试用例 6：边界场景 - 模糊请求

### 输入

```
帮我做个逆变器的方案设计。
```

### 预期行为

| 检查项 | 预期结果 |
|--------|----------|
| 技能加载 | 应加载 `embedded-design` 技能 |
| 方向判断 | 应询问用户需要哪个方向，或默认输出全部四个方向 |
| 输出范围 | 不应过度扩展到器件选型、PCB 设计等非架构内容 |

### 验证标准

- [ ] 不输出 PCB layout 或器件 datasheet
- [ ] 聚焦在软件/固件架构层面
- [ ] 如果用户未指定方向，应主动确认或给出建议

---

## 测试用例 7：边界场景 - 已有设计补充

### 输入

```
我已经完成了 MCU 架构设计，现在需要补充 FPGA 侧的硬件保护方案，要求过流保护响应时间 < 500ns。
```

### 预期行为

| 检查项 | 预期结果 |
|--------|----------|
| 技能加载 | 应加载 `embedded-design` 技能 |
| 参考文档 | 仅读取 `references/fpga-design.md` |
| 增量输出 | 仅输出 FPGA 保护相关内容，不重复 MCU 设计 |
| 时序约束 | 输出时序预算满足 < 500ns 要求 |

### 验证标准

- [ ] 不重复输出 MCU 架构内容
- [ ] 保护逻辑时序预算 < 500ns
- [ ] 包含 ADC 采样 → 滤波 → 比较 → 锁存 → PWM 关断全链路

## 测试执行方法

### 手动测试

1. 在新的 Codex 对话中输入测试用例的「输入」内容
2. 检查输出是否满足「验证标准」中的所有检查项
3. 记录通过/失败项

### 自动化测试（推荐）

```bash
# 使用 Codex subagent 进行独立验证
# 在 Codex 中执行：
# 1. 启动新对话
# 2. 输入测试用例
# 3. 对照验证标准逐项检查
```
