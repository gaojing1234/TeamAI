# 嵌入式系统方案设计

为电力电子（逆变器/变流器）项目生成全面的嵌入式系统架构设计，覆盖 MCU、DSP、FPGA 和 Linux 四个开发方向。

## 适用场景

- 设计新的嵌入式控制系统架构
- 规划多芯片（MCU+DSP+FPGA+Linux）系统分区
- 定义 RTOS 任务调度与优先级策略
- 设计故障保护与隔离机制
- 规划 Bootloader、OTA 与安全启动流程
- 制定子系统间通信协议

## 工作流程

### 第一步：确定开发方向

判断用户需要哪个（哪些）方向：

| 开发方向 | 关注重点 | 核心输出物 |
|----------|----------|------------|
| **MCU** | RTOS 选型、任务划分、故障隔离、Bootloader、安全启动 | 软件架构图、状态机、流程图 |
| **DSP** | 控制算法（PQ/VSG）、PLL、电流环、MPPT、开关频率 | 软件架构图、状态机、控制框图 |
| **FPGA** | 数据通路、硬件化保护、抽取滤波、RMS 计算、通信 IP | Verilog 顶层框架、时钟/复位规划、IP-XACT |
| **Linux** | 进程划分、驱动框架、通信栈、存储与 OTA | 软件架构图、状态机、流程图 |

### 第二步：加载方向参考文档

读取对应方向的设计参考文件：

- `references/mcu-design.md` — MCU 架构设计模式
- `references/dsp-design.md` — DSP 控制架构设计模式
- `references/fpga-design.md` — FPGA 数据通路与保护设计模式
- `references/linux-design.md` — Linux 应用架构设计模式

### 第三步：生成设计产物

每个方向需输出：

1. **软件架构** — 分层图，展示模块、接口与数据流
2. **状态机** — 系统状态、转换条件、守卫条件与动作
3. **流程图** — 关键操作流程（启动、故障处理、模式切换）
4. **任务/进程表** — 优先级、周期、最坏执行时间、依赖关系
5. **接口定义** — 通信协议、数据格式、时序要求

### 第四步：跨方向集成

当涉及多个方向时，还需输出：

- **接口控制文档（ICD）** — CAN/SPI/UART 协议定义
- **故障传播图** — 故障在 FPGA → MCU → DSP → Linux 之间的流转
- **时序预算** — 跨子系统的端到端延迟分析

## 输出格式

### 架构图

使用 ASCII 文本或 Mermaid 兼容语法：
- 分层架构（硬件 → 驱动 → OS → 中间件 → 应用）
- 任务调度时间线
- 通信拓扑

### 状态机

每个状态机包含：
- 状态定义及入口/出口动作
- 转换条件（守卫）
- 事件触发器
- 超时处理

### 流程图

覆盖关键路径：
- 系统启动与初始化
- 故障检测与恢复
- 模式切换（如 PQ ↔ VSG）
- OTA 升级流程

## 设计约束

### 通用约束

- 实时响应：FPGA < 1µs，MCU < 1ms，DSP < 10ms，Linux < 100ms
- 故障隔离：4 层保护（硬件 → 软件 → 控制 → 系统）
- 通信：控制链路使用确定性协议，监控链路使用标准协议

### MCU 专项约束

- RTOS：推荐 FreeRTOS（具备 IEC 61508 认证路径）
- 静态内存分配（避免堆碎片）
- 所有关键任务必须看门狗监控

### DSP 专项约束

- 控制环执行：电流环 < 10µs，电压环 < 100µs
- 定点运算需饱和保护
- 并网模式 PLL 锁定时间 < 20ms

### FPGA 专项约束

- 跨时钟域需使用同步器
- 保护逻辑流水线深度 ≤ 32 级
- 资源利用率 < 80%（确保时序收敛）

### Linux 专项约束

- 进程隔离，使用独立地址空间
- 控制相关任务需打实时补丁
- 使用日志文件系统（抗掉电）
