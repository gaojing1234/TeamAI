# Embedded Full-Chain Development

> **[本机口径仲裁 · 2026-10-14 添加 · 可整段删除还原]**
> 本技能负责**工程流程**：项目脚手架、芯片分级（LV1–LV3）、架构、构建、烧录、测试。
> 涉及**编码规范**（命名 / 注释 / 错误处理 / 分层与函数表 / 状态机）的部分
> 一律**让位**给主口径 `embedded-c-conventions`，不要另行给出冲突的规范结论。
> 项目自身的门禁流程与硬约束（见 `~/.codex/AGENTS.md`）优先级**高于**本技能。

From project scaffolding to flash deployment — one skill for the entire embedded lifecycle.
Every section is tier-rated. Find your tier first, then apply only what matters.

References: MISRA-C:2012, CERT-C, Barr Group Embedded C Coding Standard,
FreeRTOS coding conventions, Zephyr/ESP-IDF/PlatformIO project patterns,
Embedded Artistry, Interrupt (Memfault).

## 1. Quick Tier Rating

Before writing any code, determine the target tier. This takes 30 seconds and
governs every subsequent section.

### Method A — By Chip Family (fastest)

| Tier | Chip Families | Flash | RAM | Typical Use |
|------|--------------|-------|-----|-------------|
| **LV1** | 8051, STC89/STC12, ATtiny, ATmega328P, STM8, Padauk | < 64 KB | < 8 KB | Bare-metal toys, simple controllers |
| **LV2** | STM32F0/F1/F3/F4, ESP32, nRF52, RP2040, GD32, CH32, SAM D/E, MSP430, PIC24/dsPIC | 64 KB – 1 MB | 8 KB – 256 KB | RTOS optional, most real products |
| **LV3** | STM32H7, STM32MP1, i.MX RT, ESP32-S3, nRF5340, RZ/A1, any Linux-capable SoC | > 1 MB | > 256 KB | RTOS mandatory or Linux, complex peripherals |

### Method B — By Specs (when chip is unknown)

Ask the user or read from the project config:
1. Flash size? → < 64K = LV1, 64K–1M = LV2, > 1M = LV3
2. RAM size? → < 8K = LV1, 8K–256K = LV2, > 256K = LV3
3. RTOS? → No = LV1/LV2, Yes = LV2/LV3
4. FPU/DSP/MMU? → Any = LV3

**When in doubt, pick the higher tier.** Over-specifying is cheaper than debugging on constrained hardware.

### Output

After rating, state:
```
Tier: LV2
Chip: STM32F103C8T6
Flash: 64 KB | RAM: 20 KB
Applicable rules: [list section numbers that apply]
```

## 2. Project Scaffolding

### LV1 — Minimal

```
project/
├── Makefile
├── src/
│   └── main.c
├── inc/
│   └── config.h
└── build/              # gitignore
```

### LV2 — Standard (recommended)

Borrowed from PlatformIO `src/lib/include/test` + STM32CubeMX generated structure.

```
project/
├── CMakeLists.txt
├── .clang-format
├── .clang-tidy
├── src/
│   ├── main.c
│   └── app/            # Business logic modules
│       ├── state_machine.c
│       └── state_machine.h
├── include/            # Public headers (project-wide API)
├── lib/
│   ├── bsp/            # Board Support Package
│   │   ├── bsp_clock.c
│   │   ├── bsp_pin.c
│   │   └── bsp_pin.h
│   ├── drivers/        # Peripheral drivers
│   │   ├── i2c_bus.c
│   │   ├── spi_bus.c
│   │   └── uart_drv.c
│   └── middleware/      # RTOS, lwIP, FatFS, LVGL, etc.
├── config/             # Configuration headers
│   ├── FreeRTOSConfig.h
│   ├── lv_conf.h
│   └── lwipopts.h
├── test/               # Unit tests (Unity/Ceedling)
│   ├── test_state_machine.c
│   └── test_i2c_bus.c
├── tools/              # Flash/debug scripts
│   └── flash.sh
└── build/              # gitignore
```

### LV3 — Advanced

Add to LV2 structure:

```
├── components/         # Self-contained modules with own CMakeLists.txt
│   ├── net/
│   │   ├── CMakeLists.txt
│   │   ├── Kconfig
│   │   ├── include/
│   │   └── src/
│   └── storage/
│       ├── CMakeLists.txt
│       ├── Kconfig
│       ├── include/
│       └── src/
├── Kconfig             # Top-level configuration menu
├── sdkconfig           # Generated by menuconfig (gitignore)
└── sdkconfig.defaults  # Checked-in defaults
```

### CubeMX Projects

For STM32CubeMX-generated projects, the structure is:
```
project/
├── project.ioc         # Single source of truth for hardware config — VERSION THIS
├── Core/
│   ├── Inc/
│   └── Src/
│       └── main.c      # Contains /* USER CODE BEGIN */ markers
├── Drivers/
│   ├── CMSIS/
│   └── STM32xxxx_HAL_Driver/
├── Middlewares/
└── Startup/
```

**Rule:** Never edit between `USER CODE BEGIN` and `USER CODE END` markers outside
those blocks — CubeMX will overwrite on regeneration. Place all user code inside
these markers.

## 3. Architecture Layering

### Five-Layer Model (LV2/LV3)

```
┌─────────────────────────────────────────────────────┐
│  APP/         Business logic, state machines, tasks │
├─────────────────────────────────────────────────────┤
│  SERVICE/     Middleware wrappers: RTOS, lwIP,       │
│               FatFS, LVGL, protocol stacks           │
├─────────────────────────────────────────────────────┤
│  DRIVER/      Peripheral drivers: I2C, SPI, UART,   │
│               GPIO, Timer, ADC, DMA                  │
├─────────────────────────────────────────────────────┤
│  HAL/         Hardware Abstraction: vendor SDK       │
│               wrapped behind thin adapters           │
├─────────────────────────────────────────────────────┤
│  BSP/         Board init: clock tree, pin mux,       │
│               NVIC, power rail, crystal config       │
└─────────────────────────────────────────────────────┘
```

### Three-Layer Model (LV1)

```
┌─────────────────────────────┐
│  APP/    Business + main()  │
├─────────────────────────────┤
│  DRIVER/ Peripheral access  │
├─────────────────────────────┤
│  BSP/    Clock + pin init   │
└─────────────────────────────┘
```

### Dependency Rules (strict)

1. **Upper depends on lower ONLY.** Lower layers never `#include` from upper layers.
2. **Same-layer modules** communicate through public headers / function-pointer interfaces — not by reaching into each other's internals.
3. **Callbacks** pass function pointers DOWN through init; lower layers must never know upper-layer symbols.
4. **Vendor SDK isolation:** wrap vendor HAL (`HAL_*`, `LL_*`, etc.) inside HAL/ thin adapters.
   Upper layers are portable to a new MCU by replacing HAL/ + BSP/ only.
5. **SERVICE/ layer** exists to decouple APP from specific middleware implementations.
   APP calls `svc_mutex_lock()`, not `osMutexWait()`.

### Why SERVICE/ Fixes the Old BSP/RTOS Conflict

The old design put RTOS in "Middlewares/" and BSP at the bottom, creating ambiguity:
- "Does BSP run bare-metal or under RTOS?"
- "Where do RTOS-dependent drivers live?"

New answer:
- **BSP** is always bare-metal (runs before RTOS starts).
- **DRIVER** is RTOS-agnostic (uses HAL, not OS calls).
- **SERVICE** wraps RTOS and middleware for APP to use.
- If a driver needs RTOS (e.g., DMA + semaphore), that goes in SERVICE/, not DRIVER/.

## 4. Coding Standards

### 4.1 Naming Conventions

| Construct | Style | Example | LV1 | LV2 | LV3 |
|-----------|-------|---------|-----|-----|-----|
| File | `snake_case` | `i2c_bus.c` | — | must | must |
| Type (struct/enum/typedef) | `snake_case_t` | `ring_buffer_t` | — | must | must |
| Function | `module_verb_object` | `uart_send_byte()` | — | must | must |
| Public function | module-prefixed | `mpu6050_read_accel()` | — | must | must |
| Static function | `snake_case`, no prefix | `parse_frame()` | — | — | must |
| Macro / constant | `UPPER_SNAKE_CASE` | `MAX_BUF_LEN` | must | must | must |
| Enum value | `UPPER_SNAKE_CASE`, type-prefixed | `UART_STATE_IDLE` | — | must | must |
| Global variable | `g_` prefix | `g_system_tick` | — | must | must |
| File-local variable | `s_` prefix | `s_rx_buf[64]` | — | — | must |

### 4.2 Types

- Use **fixed-width types** from `<stdint.h>`: `uint8_t`, `int32_t`, etc.
  Never `int` / `long` for protocol fields, registers, or hardware-facing structs.
- Use `size_t` for sizes/counts, `bool` from `<stdbool.h>`, `uintptr_t` for pointer-sized integers.
- `const`-qualify everything not mutated. Tables placed in flash MUST be `const`.
- `volatile` for: memory-mapped registers, variables shared with ISRs, variables modified by DMA.
  `volatile` is NOT a substitute for atomicity or memory barriers.
- Avoid `float` / `double` on cores without an FPU. Prefer fixed-point (Q-format) or integer math.
- Be explicit about endianness at protocol boundaries.

### 4.3 Memory

| Rule | LV1 | LV2 | LV3 |
|------|-----|-----|-----|
| Prefer static allocation | suggest | must | must |
| No `malloc`/`free` in ISR | suggest | must | must |
| No heap at all | — | suggest | must |
| No VLAs | suggest | must | must |
| No recursion | suggest | must | must |
| Stack budget reviewed per task | — | must | must |
| No large local arrays (>256 B) | — | must | must |
| Section placement (DMA, flash, TCM) | — | — | must |

### 4.4 Macros and Constants

- Magic numbers ⇒ named `#define` or `enum`. Prefer `enum` for related sets.
- Function-like macros: parenthesize every argument; wrap multi-statement in `do { ... } while (0)`.
- Prefer `static inline` over function-like macros when types are known.
- Macros must NOT hide control flow (`return`, `goto`, `break` inside a macro body).
- **LV1:** Minimize macro usage — too many macros cause code bloat on tiny flash.
- **LV2/LV3:** Build configuration macros live in `config/` headers, not scattered across modules.

### 4.5 Header Inclusion

| # | Rule | Example |
|---|------|---------|
| 1 | The .c file's own header first | `#include "uart_drv.h"` |
| 2 | C standard / system headers `<>` | `<stdint.h>`, `<string.h>` |
| 3 | Third-party / vendor SDK `<>` | `<stm32f4xx_hal.h>` |
| 4 | Project headers `""` — near to far | same dir → parent → siblings |
| 5 | Include ONLY what is used | no "just in case" headers |

- `<>` for toolchain/system/vendor SDK; `""` for project code.
- Forward-declare in headers when only a pointer is needed; full include in the .c file.
- Include guards: `#ifndef NAME_H / #define NAME_H / #endif // NAME_H`
- **LV1:** This ordering is advisory. LV2/LV3: mandatory.

### 4.6 File Conventions

**Naming:** `snake_case.c` / `snake_case.h`. Filename matches primary module.

**.c file content order:**
1. File header comment (see Section 9)
2. `#include` (per ordering above)
3. `#define` constants and function-like macros
4. `typedef` / `struct` / `enum`
5. `static` (file-local) variables
6. `extern` / global variables (avoid; prefer accessor functions)
7. `static` function prototypes
8. Public function definitions
9. `static` function definitions

**.h files** expose ONLY the public interface. Internal types and statics belong in the .c
or in a private header (`*_priv.h`) included only by sibling .c files.

## 5. Concurrency, Interrupts, Real-Time

### LV1 — Bare Metal

- Use polling or finite state machines (FSM). No ISR-shared state issues.
- If an ISR is needed, keep it under 20 instructions. Set a flag, return.
- No blocking, no printf, no complex logic in ISR.

### LV2 — ISR + RTOS

- **ISRs are short.** Capture data, post to a queue or set a flag, return.
  No blocking, no logging, no malloc, no `printf`.
- **Shared with ISR ⇒ `volatile` + atomic access** (single-word writes on the target ISA),
  or protected by a critical section. Document which.
- **Critical sections are paired, scoped, and minimal.**
  Use `ENTER_CRITICAL()` / `EXIT_CRITICAL()` that save/restore PRIMASK.
  Bare `__disable_irq()` corrupts nested critical sections.
- **RTOS primitives:** mutex for mutual exclusion (with priority inheritance);
  semaphore for signaling. From an ISR, use only `*FromISR` variants.
- **Reentrancy:** any function callable from both task and ISR contexts MUST be reentrant —
  no static locals, no unguarded shared state.

### LV3 — Full RTOS + Advanced

All LV2 rules, plus:
- **WCET analysis:** loops in ISRs and high-priority tasks need bounded iteration count.
  Document worst-case timing for hard-real-time paths.
- **Watchdog:** kicked from a low-priority task that proves the system is making progress —
  not from a timer ISR (which kicks even when tasks are starved).
- **Priority inversion:** use mutexes with priority inheritance, or priority ceiling protocol.
- **Stack watermarking:** monitor per-task stack high-water marks in debug builds.
- **Deadlock detection:** enable RTOS trace hooks in debug builds.

## 6. Memory & Power

### Memory Layout

- **DMA buffers** → non-cached / aligned region. Use `__attribute__((aligned(N)))`.
- **Large constants** → flash (mark `const`). On AVR, use `PROGMEM`.
- **Hot paths** → tightly-coupled memory (ITCM/DTCM) when available (LV3).
- **Overlay/union** rarely-used code segments into shared RAM regions (LV1).
- **Alignment:** DMA descriptors, cache-line-sized structs, and packed protocol structs
  need explicit alignment annotations.

### Power Management

- **On-demand peripheral activation:** sensors, radios, amplifiers powered on only while
  the consuming task is active. Put peripherals to sleep immediately when done.
  A peripheral left running "just in case" can double baseline current.
- **Peripheral sleep is explicit:** wrap enable/disable in driver API
  (`sensor_wakeup()` / `sensor_sleep()`).
- **Low-power modes are tiered:**
  - RUN — full operation
  - SLEEP/STOP — core halted, peripherals selectively active, wake on RTC or external IRQ
  - OFF — power rail disabled, only VBAT domain alive for RTC
  Document which wake sources are active in each tier and expected current.
- **Wake-up validation:** after waking, re-read the peripheral's device-ID or status register
  before trusting its data.

## 7. Error Handling

- Return an explicit status code (`enum` / `int`); reserve `0` or `*_OK` for success.
  Don't overload one return value for "value or error" without a clear contract.
- `assert()` for **programmer errors** (conditions impossible if code is correct).
  Compile out in release if footprint matters; replace with a logged trap if uptime matters.
- No C++ exceptions in firmware unless the platform explicitly supports them and the cost
  has been measured.
- Validate at boundaries (user input, peripheral probe, deserialization), trust internal invariants.
  Never silently swallow a peripheral error.

### Peripheral Probe with Retry

I2C/SPI sensors can fail their first init due to power-up timing, bus capacitance, or contact issues.
Always probe with a bounded retry loop:

```c
#define PROBE_RETRY_MAX  3

bool sensor_probe(sensor_t *dev)
{
    for (uint8_t i = 0; i < PROBE_RETRY_MAX; i++) {
        if (sensor_read_id(dev) == dev->expected_id) {
            return true;
        }
    }
    return false;  // caller handles failure — degrade, fallback, or report
}
```

Key points:
- Retry count is small and bounded — infinite retry hides systematic failures.
- Each attempt re-runs the full init sequence, not just the failing register write.
- The caller handles the final error state.

## 8. Toolchain & Build

### Build System Selection

| Feature | LV1 | LV2 | LV3 |
|---------|-----|-----|-----|
| Build system | Makefile | CMake | CMake + Kconfig |
| Compiler | SDCC / Keil / avr-gcc | arm-none-eabi-gcc | arm-none-eabi-gcc |
| Warnings | `-Wall` | `-Wall -Wextra -Werror` | + `-Wshadow -Wconversion -Wundef` |
| Static analysis | — | cppcheck | cppcheck + MISRA addon |
| Formatter | — | .clang-format | .clang-format |
| Unit tests | — | Unity / Ceedling | Unity + CMock / Ceedling |
| Size optimization | `-Os` | `-Os -ffunction-sections -fdata-sections` | + `-flto -Wl,--gc-sections` |

### CMake Cross-Compilation Template (LV2/LV3)

```cmake
set(CMAKE_SYSTEM_NAME Generic)
set(CMAKE_SYSTEM_PROCESSOR arm)
set(CMAKE_C_COMPILER arm-none-eabi-gcc)
set(CMAKE_CXX_COMPILER arm-none-eabi-g++)
set(CMAKE_ASM_COMPILER arm-none-eabi-gcc)
set(CMAKE_TRY_COMPILE_TARGET_TYPE STATIC_LIBRARY)

set(MCU_FLAGS "-mcpu=cortex-m4 -mthumb -mfloat-abi=hard -mfpu=fpv4-sp-d16")
set(CMAKE_C_FLAGS "${MCU_FLAGS} -Wall -Wextra -Werror -ffunction-sections -fdata-sections -Os")
set(CMAKE_EXE_LINKER_FLAGS "${MCU_FLAGS} -Wl,--gc-sections -specs=nano.specs")
```

### Post-Build

```bash
# Generate binary
arm-none-eabi-objcopy -O binary firmware.elf firmware.bin

# Check size
arm-none-eabi-size firmware.elf

# Generate hex (for some loaders)
arm-none-eabi-objcopy -O ihex firmware.elf firmware.hex
```

### Flash/RAM Budgeting

- Use `-Os -ffunction-sections -fdata-sections -flto -Wl,--gc-sections`.
- Use **newlib-nano** (`--specs=nano.specs`) instead of full newlib.
- Replace `printf` with lightweight alternatives (e.g., `printf`-lite, custom formatting).
- Replace floating-point with fixed-point arithmetic.
- Audit includes — remove unused headers.
- Analyze with `nm`, `size`, `objdump`, or [bloaty](https://github.com/google/bloaty).
- Review `.map` files each release for unexpected size growth.

### Static Analysis (LV2/LV3)

```bash
# cppcheck with MISRA addon
cppcheck --enable=all --std=c11 --platform=unix32 \
         --addon=misra.json --xml --xml-version=2 \
         src/ 2> cppcheck_report.xml

# clang-tidy
clang-tidy src/*.c -- -Iinclude -Ilib/bsp -Ilib/drivers
```

### Unit Testing (LV2/LV3)

Use Unity + CMock + Ceedling (ThrowTheSwitch.org):

```bash
# Install
gem install ceedling

# Create test project
ceedling new my_project

# Run all tests
ceedling test:all

# Run specific test
ceedling test:test_state_machine
```

Test structure:
```
test/
├── test_state_machine.c    # Unity test file
├── test_i2c_bus.c
├── support/
│   └── mock_hal.h          # CMock-generated mocks
└── unity_config.h
```

**Rule:** Hardware-dependent modules get mocked HAL stubs. Logic modules run on host.
Never skip tests because "it only works on target."

## 9. Documentation Standards

### File Header (mandatory for LV2/LV3, recommended for LV1)

```c
/**
 * @file    mpu6050_drv.c
 * @brief   IMU driver — accel/gyro sample read, FIFO drain.
 * @author  <name>
 * @note    Datasheet rev 4.2; errata 3.1 sample-rate jitter workaround.
 */
```

Date / version / change history are optional — VCS is the source of truth.

### Function Comments

- **Public functions:** purpose, parameter contracts (units, ranges, ownership),
  return semantics, side effects, *ISR-safe? blocking?*
- **Special parameters:** ownership and lifetime — who allocates, who frees,
  when the buffer must remain valid.
- Place comments **before** the code, not trailing.

```c
/**
 * @brief Read accelerometer XYZ samples from the MPU6050 FIFO.
 *
 * @param[out] buf   Destination buffer, must hold at least @p count * 6 bytes.
 * @param[in]  count Number of samples to read. Range: [1, 128].
 * @return Number of samples actually read, or negative error code.
 * @retval -EINVAL  buf is NULL or count is 0.
 * @retval -EIO     I2C bus error (NACK or timeout).
 *
 * @pre    I2C bus initialized via i2c_bus_init().
 * @note   NOT ISR-safe. Blocks on I2C transfer.
 */
int16_t mpu6050_read_accel(int16_t *buf, uint8_t count);
```

### Code-Level Comments — Write WHY, not WHAT

Good targets for a comment:
- Hardware errata workarounds (cite the erratum number)
- Non-obvious timing assumptions ("must run within 10us of the edge")
- Magic offsets dictated by silicon
- Re-orderings that look wrong but are required for compiler/peripheral/cache behavior

Tagged comments:
- `// TODO: <what + why>` — incomplete code
- `// FIXME: <symptom>` — known broken
- `// NOTE: <surprise>` — non-obvious behavior worth flagging
- `// HACK: <workaround>` — temporary, reference a ticket or erratum

### Preprocessor Annotations

Every non-trivial `#else` / `#endif` gets a trailing comment:
```c
#ifdef FEATURE_X
  // ...
#else  // !FEATURE_X
  // ...
#endif // FEATURE_X
```

### LV3 — Module Grouping

Use Doxygen `@defgroup` for logical module grouping:
```c
/**
 * @defgroup MPU6050_Driver MPU6050 IMU Driver
 * @brief    Inertial measurement unit driver over I2C.
 * @{
 */
// ... module code ...
/** @} */ // end of MPU6050_Driver
```

## 10. Code Review Checklist

When reviewing embedded code, check each category below. Items are marked with
minimum tier level — if your project is LV1, skip LV2/LV3 items.

### Memory & Resources

- [ ] No `malloc` / `free` in ISR [LV2+]
- [ ] No VLAs [LV2+]
- [ ] Stack usage reviewed per task (no large local arrays) [LV2+]
- [ ] `volatile` on ISR-shared and DMA-touched data [LV2+]
- [ ] DMA buffers properly aligned [LV2+]
- [ ] RAM/ROM footprint within budget [LV2+]
- [ ] No recursion [LV2+]

### Concurrency & ISRs

- [ ] Shared data protected (mutex, critical section, lock-free) [LV2+]
- [ ] ISRs short — no blocking, no malloc, no printf [LV2+]
- [ ] Critical sections paired (ENTER/EXIT) [LV2+]
- [ ] ISR uses `*FromISR` RTOS variants [LV2+]
- [ ] Priority inversion addressed [LV3]
- [ ] WCET bounded for hard-real-time paths [LV3]

### Hardware Interaction

- [ ] Register access is atomic where needed [LV2+]
- [ ] Correct endianness at protocol boundaries [LV2+]
- [ ] Proper peripheral init sequence [all]
- [ ] Watchdog kicked from task, not timer ISR [LV3]
- [ ] Pin mux / clock config verified against datasheet [all]

### Error Handling

- [ ] Return values always checked [all]
- [ ] Fault/edge cases handled (timeout, NACK, bus error) [all]
- [ ] Fail-safe behavior on critical errors [all]
- [ ] Assert enabled in debug, disabled in release [LV2+]
- [ ] Peripheral probe uses bounded retry loop [LV2+]

### Safety & Reliability

- [ ] No floating-point in ISR (unless FPU context saved) [LV2+]
- [ ] Safe string functions (`snprintf` vs `sprintf`) [LV2+]
- [ ] Integer overflow/underflow protection [LV2+]
- [ ] Signed/unsigned mismatch avoided [all]
- [ ] Bitwise operations correct (masking, shifting) [all]

### Code Quality

- [ ] Magic numbers replaced with `#define` or `enum` [all]
- [ ] Consistent naming conventions [LV2+]
- [ ] Dead/unreachable code removed [all]
- [ ] State machines have all transitions defined [LV2+]
- [ ] HAL/abstraction layers maintain portability [LV2+]
- [ ] No implicit type conversions across signedness [LV2+]
- [ ] `switch` has `default`; every case ends in `break` [all]

### Power & Timing

- [ ] Peripherals powered on demand, sleep when idle [LV2+]
- [ ] Low-power modes correctly implemented [LV2+]
- [ ] Timing-critical sections identified and bounded [LV2+]
- [ ] No polling where interrupts should be used [all]

### Build & Deployment

- [ ] Compiler warnings enabled (`-Wall -Wextra -Werror`) [LV2+]
- [ ] Linker script reviewed (sections, memory regions) [LV2+]
- [ ] Version info / firmware metadata included [LV2+]
- [ ] Map file checked for unexpected growth [LV2+]

## 11. Flash & Debug

### Tool Selection Guide

| Tool | Best For | Supports | Command |
|------|----------|----------|---------|
| **probe-rs** | Modern default, ARM + RISC-V | ST-Link, DAPLink, J-Link, FTDI, ESP USB JTAG | `probe-rs run --chip STM32F401RE firmware.elf` |
| **OpenOCD** | Broadest legacy support | All major probes | `openocd -f interface/stlink.cfg -f target/stm32f4x.cfg` |
| **J-Link** | Production / professional | SEGGER probes | `JLinkExe -device STM32F401RE -if SWD -speed 4000` |
| **STM32CubeProgrammer** | ST official | ST-Link | `STM32_Programmer_CLI -c port=SWD -w firmware.bin 0x08000000` |
| **esptool** | ESP32 family | USB-UART | `esptool.py --chip esp32 write_flash 0x0 firmware.bin` |
| **avrdude** | AVR / Arduino | USBasp, Arduino bootloader | `avrdude -p m328p -c arduino -P COM3 -U flash:w:firmware.hex:i` |
| **stcgal** | STC 8051 | USB-UART | `stcgal -p COM3 -b 115200 firmware.hex` |
| **pyocd** | ARM CMSIS-DAP | DAPLink | `pyocd flash -t stm32f401re firmware.hex` |

### Post-Flash Verification

After flashing, always verify:
1. Firmware starts (check serial output or LED blink)
2. Version string matches expected build
3. No hard fault on startup (check fault registers if debug probe available)

## 12. Common Mistakes

| # | Mistake | Impact | LV |
|---|---------|--------|-----|
| 1 | Mixing `<>` and `""` for the same header | Build fragility | 2+ |
| 2 | Pulling in headers "just in case" | Flash bloat, hidden deps | 2+ |
| 3 | Lower-layer code referencing upper symbols | Architecture violation | 2+ |
| 4 | `malloc` / `printf` / long work inside ISR | Crash, heap corruption | 2+ |
| 5 | Missing `volatile` on ISR-shared / DMA data | Works in -O0, fails in -O2 | 2+ |
| 6 | Treating `volatile` as atomicity | Race condition | 2+ |
| 7 | Bare `__disable_irq()` without save/restore | Nested critical section corruption | 2+ |
| 8 | `int` instead of `uint32_t` for registers | Silent breakage on port | all |
| 9 | VLAs or large stack arrays | Stack overflow under load | 2+ |
| 10 | `assert` left active in release | Unexpected reset in production | 2+ |
| 11 | Comments restating code instead of WHY | Noise, maintenance burden | all |
| 12 | Missing trailing comments on `#endif` | Unreadable nested preprocessor | 2+ |
| 13 | Sensors left powered on after use | Battery drain | 2+ |
| 14 | Peripheral init tried once, no retry | Single bus glitch disables feature | 2+ |
| 15 | Watchdog kicked from timer ISR | Kicks even when tasks starved | 3 |
| 16 | Using `int` for bit fields | Width is compiler-dependent | all |
| 17 | Assuming host endianness matches wire | Silent data corruption on port | 2+ |
| 18 | No `default` in `switch` over hardware register | Unhandled states cause lockup | all |
| 19 | Global variables without accessors | Untestable, hard to add locking | 2+ |
| 20 | Forward-declaring struct in header but defining in .c | Opaque pointer works; full struct breaks | 2+ |

## Appendix: MISRA-C Quick Reference (LV2 Core / LV3 Full)

These rules apply during **code review**, not during initial coding.
During coding, focus on writing correct code; enforce MISRA at review time.

### LV2 — 10 Core Rules

| Rule | Description | Why |
|------|-------------|-----|
| 10.3 | No narrowing type conversions | Prevents silent truncation |
| 11.3 | No cast between incompatible pointer types | Prevents aliasing/alignment bugs |
| 12.1 | Precedence made explicit with parentheses | Eliminates ambiguity |
| 14.4 | Controlling expressions must be essentially Boolean | Prevents `if(x = 5)` |
| 15.7 | All if/else-if chains must end with else | Every path is intentional |
| 17.7 | Return value of non-void function must be used | Catches ignored error codes |
| 21.3 | No dynamic memory allocation | Heap fragmentation unacceptable |
| 2.1 | No unreachable code | Dead paths mask logic errors |
| 2.2 | No dead code | Same rationale |
| 1.3 | No undefined behavior | The foundational safety rule |

### LV3 — Full Mandatory + Required

Add all Mandatory and Required rules from MISRA-C:2012. Common additions:

| Rule | Description |
|------|-------------|
| 8.7 | Objects should have internal linkage when possible |
| 8.13 | Pointer param should be `const` if not modified |
| 11.5 | No conversion from `void*` to object pointer |
| 2.7 | Unused function parameters must be documented |
| 8.9 | Objects should be defined at block scope |

**Deviation process:** Any deviation from a Required rule MUST be documented with
rationale in a deviation log. An undocumented deviation is a defect.
